Git이란?

Git은 파일이 바뀌어 온 기록을 저장하고 관리하는 분산 버전 관리 시스템입니다. 작업한 내용을 "커밋"이라는 단위로 저장해 두면 언제든 예전 상태로 돌아가거나, 무엇이 언제 왜 바뀌었는지 확인할 수 있습니다.

GitHub는 Git 저장소를 인터넷에 올려 두고 공유하는 서비스입니다. 이 홈페이지도 GitHub 저장소에 올린 파일이 GitHub Pages로 자동 배포되어 보이는 것입니다.

핵심 개념

저장소 (Repository) Git이 관리하는 프로젝트 폴더입니다. 숨김 폴더 .git에 모든 기록이 저장됩니다.
커밋 (Commit) 특정 시점의 파일 상태를 저장한 기록입니다. 메시지와 고유 ID(해시)를 가집니다.
스테이징 영역 (Staging Area) 다음 커밋에 포함할 변경 사항을 골라 담아 두는 곳입니다.
브랜치 (Branch) 독립적인 작업 줄기입니다. 기본 브랜치는 보통 main입니다.
원격 저장소 (Remote) GitHub처럼 인터넷에 있는 저장소입니다. 기본 이름은 origin입니다.
HEAD 지금 내가 보고 있는 브랜치 또는 커밋을 가리키는 표시입니다.

작업 흐름

파일을 수정한 뒤 GitHub에 올라가기까지 네 단계를 거칩니다.

작업 폴더파일을 수정하는 곳
git add
스테이징 영역커밋할 내용 선택
git commit
로컬 저장소내 컴퓨터의 기록
git push
원격 저장소GitHub

반대로 GitHub에 있는 최신 내용을 내 컴퓨터로 가져올 때는 git pull을 사용합니다.

처음 설정

컴퓨터에서 Git을 처음 쓸 때 한 번만 하면 됩니다. 커밋에 기록될 이름과 이메일을 정합니다.

git config --global user.name "내 이름"
git config --global user.email "내이메일@example.com"
git config --list            # 설정 확인
명령어설명
git init현재 폴더를 새 Git 저장소로 만듭니다.
git clone <주소>GitHub 저장소를 내 컴퓨터로 복제합니다.

기본 명령어

명령어설명
git status바뀐 파일, 스테이징된 파일, 아직 추적하지 않는 파일을 보여 줍니다. 가장 자주 쓰는 명령어입니다.
git add <파일>파일의 변경 사항을 스테이징 영역에 올립니다.
git add .현재 폴더의 모든 변경 사항을 스테이징합니다.
git commit -m "메시지"스테이징된 내용을 하나의 커밋으로 저장합니다.
git diff아직 스테이징하지 않은 변경 내용을 줄 단위로 보여 줍니다.
git diff --staged스테이징된(커밋 예정인) 변경 내용을 보여 줍니다.
git log커밋 기록을 보여 줍니다.
git log --oneline커밋 기록을 한 줄씩 간단하게 보여 줍니다.
git show <커밋ID>특정 커밋에서 무엇이 바뀌었는지 보여 줍니다.
커밋 메시지 팁 — 무엇을 바꿨는지 한눈에 알 수 있게 씁니다. 예: Switch web programming pages to gray theme, 메인 페이지 카드 추가

브랜치

새 기능을 실험할 때 브랜치를 만들어 작업하면 main에 영향을 주지 않습니다. 완성되면 main에 합칩니다.

명령어설명
git branch브랜치 목록을 보여 줍니다. * 표시가 현재 브랜치입니다.
git branch <이름>새 브랜치를 만듭니다.
git switch <이름>다른 브랜치로 이동합니다. (예전 방식: git checkout)
git switch -c <이름>새 브랜치를 만들고 바로 이동합니다.
git merge <이름>지정한 브랜치의 내용을 현재 브랜치에 합칩니다.
git branch -d <이름>합쳐진 브랜치를 삭제합니다.

원격 저장소

명령어설명
git remote -v연결된 원격 저장소 주소를 보여 줍니다.
git remote add origin <주소>원격 저장소를 origin이라는 이름으로 연결합니다.
git push origin main로컬 커밋을 GitHub의 main 브랜치에 올립니다.
git push -u origin main처음 올릴 때 사용합니다. 이후로는 git push만 써도 됩니다.
git pullGitHub의 최신 내용을 가져와 현재 브랜치에 합칩니다.
git fetchGitHub의 최신 내용을 가져오기만 하고 합치지는 않습니다.

되돌리기

명령어설명
git restore <파일>아직 스테이징하지 않은 수정 내용을 버리고 마지막 커밋 상태로 되돌립니다.
git restore --staged <파일>스테이징만 취소합니다. 수정한 내용은 그대로 남습니다.
git commit --amend마지막 커밋의 메시지나 내용을 고칩니다. 이미 push한 커밋에는 쓰지 않는 것이 좋습니다.
git revert <커밋ID>지정한 커밋을 취소하는 새 커밋을 만듭니다. 이미 push한 커밋을 되돌릴 때 안전합니다.
git reset --hard <커밋ID>지정한 커밋으로 완전히 되돌리고 이후 변경 사항을 모두 지웁니다. 복구가 어려우니 주의해야 합니다.
.gitignore — 저장소에 올리지 않을 파일을 적어 두는 파일입니다. macOS가 자동으로 만드는 .DS_Store 같은 파일을 한 줄씩 적어 두면 git status에 나타나지 않습니다.

실전 예시: 홈페이지 수정 후 업로드

이 사이트의 페이지를 수정하고 GitHub Pages에 반영하는 순서입니다.

# 1. 무엇이 바뀌었는지 확인
git status
git diff

# 2. 올릴 파일만 골라서 스테이징
git add classpages/Dsgnpages.html

# 3. 커밋
git commit -m "Rename web programming 2nd semester list heading"

# 4. GitHub에 업로드 → 1~2분 뒤 사이트에 자동 반영
git push origin main
반영이 안 보일 때 — GitHub Pages는 페이지를 최대 10분 동안 캐시합니다. push한 뒤에도 예전 화면이 보이면 Cmd + Shift + R(Windows는 Ctrl + Shift + R)로 새로고침해 보세요.
